# PR description (concise changelog)

Turn the branch's changes into a PR description a reviewer can grasp without
opening a file. The diff shows *what*; the description gives the **net
effect** and the **why** the diff can't convey. Match length to the change.

## Branch context
Diff against `origin/main` (fetched quietly first) — a stale local `main`
mis-scopes the description.
- Branch: !`git branch --show-current`
- Commits vs main: !`git fetch -q origin main 2>/dev/null; git log --oneline origin/main..HEAD`
- Diff stat: !`git diff --stat origin/main...HEAD`

## Procedure
1. **Group the diff by behavior**, not by file — collapse commits and files
   into the handful of changes a reviewer cares about.
2. **Find the non-obvious why** for each change. A self-evident change needs no
   rationale.
3. **Write the title** `<type>(<optional scope>): <imperative summary>`.
   `<type>` comes from the branch prefix (`feat/…` → `feat`, `fix/…` → `fix`,
   etc. — see Git conventions in the root `AGENTS.md`). If the branch has no
   recognized prefix, ask the user; never invent a type. The summary is a
   specific one-liner you write, not the branch slug.
4. **Draft the bullets** per the rules below; present title + body for review.
5. **If `push` is given**, find the PR with
   `gh pr list --head <branch> --json number` and update it with
   `gh pr edit <n> --title "<title>" --body-file <file>`. Otherwise just
   present the description.

## Body rules
- **Bulleted changelog.** One bullet per meaningful change, imperative mood,
  most- to least-important. State the change and its effect.
- **Lead with the why** when it isn't self-evident.
- **Flag what needs scrutiny:** schema/config changes, new dependencies,
  security-relevant changes, deliberate scope cuts ("Follow-up: …").
- **Testing:** one line on what proves it. Don't paste output.
- **Omit:** empty sections, restated diffs, and co-authorship / "generated by"
  / tool-attribution trailers.

## Output format
```
Title: <type>(<scope>): <imperative summary>

- <change + effect> (<one-line why, only if non-obvious>)
- <change + effect>
- Testing: <what proves it>
```
